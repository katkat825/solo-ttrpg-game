# The sound behind the screen

`DM_PRESENCE.md` D4. `THE_TABLE.md` §7 ranks this second only to the dice and §2 says to budget
real effort here: it is **most of the DM's presence**.

**The folder is the list.** `Game.Dm.DmVoice` points an `ImpactPool` at each directory below and
nothing enumerates a file — dropping a `.wav` in is the whole of adding a sound, exactly as it is
for `samples/impacts/wood/`.

**Every sound here is wordless.** `THE_TABLE.md` §9 Q1 is resolved: the DM never speaks and no
words are voiced. Atmosphere and wordless human breath only — every *word* the DM has is text,
delivered by a hand (D5). A human-recorded "hm" is also the cleanest provenance there is
(`ASSET_MANIFEST.md`) and carries no AI-disclosure weight.

| Folder | When it plays | What goes in it |
|---|---|---|
| `tone/` | looped, under everything | the room the table is in — one long, unobtrusive bed |
| `busy/` | every ~14s at an idle table | a page turning, a pencil scratching, a chair creak, a page flipped *back* to re-check something, a quiet exhale |
| `reacts/` | on a Snag — exactly one `1` on the felt | the **"hm"**. Barely audible. Worth more than a thousand words of dialogue |
| `behind/` | before a foe swings, and sometimes for nothing (D2) | dice rattling in a cup, muffled, behind the screen |

**Empty is a supported state and this build ships in it.** With no recordings the DM says so once
at load and is silent thereafter — as present as the screen and the hands make him. `behind/`
falls back to the tray's own dice samples (M7) muffled, because D2 says outright it "reuses the
dice-audio work… not a new sound system".

**The verify step is an ear check and it is yours:** sit at an idle table with your eyes closed.
It should sound like someone is sitting behind that screen. Do something surprising and hear the
quiet reaction. None of it should loop obviously.
